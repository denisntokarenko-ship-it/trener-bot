## Важливе

**В1. Скрипт ініціалізації секретів не збережений у репо й не відтворюваний.** RUNBOOK (рядок «Секрети й вебхук — одним скриптом») каже «Ротація секрету = той самий скрипт» і дає лише `<шлях>`. Файл лежить поза репо (scratchpad/нотатки сесії), а в ньому `$repo = 'D:\01CLOud CODE\Тренер\.claude\worktrees\phase-1-05-prod-release-c0029e'` (рядок 4), `$workerUrl` і `$ownerId` зашиті. Сценарій: після мержу worktree автора знесуть (`gh pr merge --delete-branch` або clean-up) → `Set-Location` падає; ротація «тим самим скриптом» неможлива, секрет вебхука ніде не зберігається, а другого шляху RUNBOOK не дає. Виправлення: покласти скрипт у `scripts/` (без секретів, `$repo` = каталог скрипта, URL/ID — параметри), у RUNBOOK дати реальну команду.

**В2. Кроки борга F-0 (чужий id → тиша, повтор `update_id` → дедуп) у скрипті мають «свідка» лише у вигляді HTTP-кодів.** Скрипт друкує `200 200 200` (рядки 53–54), але 200 повертає і гілка «дедуп», і «чужий», і «обробив» — код не доводить ні тиші, ні дедупу. Урок власного журналу: «пройшов від людини — гіпотеза, звіряй зі слідом». Виправлення: після запуску агент читає прод (`SELECT count(*) FROM processed_updates WHERE update_id IN (900100,900101)` → 2, `users` = 0 до `/start`) і `tail` без відповідей чужому; зафіксувати це в «Перевірка 1.5» і закрити борг F-0 лише після цього. Побічно: фейки лишають 2 синтетичні рядки в `processed_updates` прода (крон приб'є за 3 доби) — згадати в RUNBOOK.

**В3. Правка `scripts/backup-prod.sh` без автоматичного тесту, а нова гілка не прогнана автором** (власне зізнання в «Мутаційній перевірці»). Я прогнав її зі стабом `npx` (shell-функція): export `PRAGMA…;` + порожній список → exit 0 з повідомленням; export з `CREATE TABLE` + порожній список → exit 1, файл видалено; мутант (`grep` → `false`) → exit 0, тобто умову ловить лише ручний прогін — у репо немає тесту, що почервонів би. Також гілка слабка: будь-який непорожній export без `CREATE TABLE` (напр. 1 байт сміття) при порожньому списку проходить «успіхом». Виправлення: тест (bash-стаб або vitest через `child_process`) на 3 випадки вище + вимога, що export порожньої БД дорівнює очікуваному рядку `PRAGMA defer_foreign_keys=TRUE;`.
