# Тренер — план MVP

## Context

Личный Telegram-бот — тренер в зале для одного человека (Денис). Сейчас вместо него: заметки или ничего; рынок — Fitbod (~$16/мес, ИИ-прогрессия), Hevy (бесплатный дневник без программ), отдельные боты КБЖУ по фото (BodyBot, Starbody). Совмещающих тренировки и еду почти нет.

Цель: бот выдаёт тренировку по программе, за 1 нажатие записывает подход, сам считает веса на следующую тренировку, хранит прогресс; позже — фото еды → калории и БЖУ, и ИИ-тренер для вопросов. Второстепенная цель — учебная: агент с инструментами, тесты на правила, git-процесс.

Стан папки: пустая (`D:\01CLOud CODE\Тренер`), только этот план.

**Главные риски, учтённые в плане:**
1. Калории по фото у LLM ошибаются на ~35–40% (старые модели), до ~20–27% если вес известен — поэтому ИИ только распознаёт продукты и граммы, цифры берутся из базы, граммы подтверждаются человеком.
2. LLM может выдумать рабочий вес — прогрессия считается чистой функцией в коде, покрытой тестами; ИИ только объясняет и предлагает.
3. Если запись подхода дольше ~5 секунд — дневник забросят. Скорость записи — ядро, а не мелочь.

## Стек и почему именно он

**Cloudflare Workers + D1 (SQLite) + Drizzle ORM + grammY + `@anthropic-ai/sdk`, TypeScript, vitest (pool workers). Хостинг $0, ИИ ~$1–2/мес.**

Критерии из опроса: $0, бот не засыпает, есть расписание (cron), бэкап средствами платформы, обслуживает один начинающий без сервера.

| Критерий | Workers + D1 | Python на Oracle Always Free | Supabase Free |
|---|---|---|---|
| Засыпание | нет | Oracle может остановить VM, если 7 дней загрузка < 20% — ровно случай личного бота | пауза после 7 дней без активности |
| Cron | Cron Triggers (5 на аккаунт на Free) | системный cron | pg_cron |
| Бэкап на бесплатном тарифе | Time Travel 7 дней | нет, всё сам | нет |
| Обслуживание | нет сервера | ОС, перезапуски, бэкапы | мало |

Workers + D1 — единственный вариант, прошедший все критерии. Знакомость (тот же стек в KOXBE bot: Drizzle, vitest workerd, preview/prod окружения) — бонус, а не причина.

**Цена выбора и компенсация:**
- **10 мс CPU на вызов** (ожидание I/O не считается) → берём у Telegram уменьшенное фото (~800 px), никакой тяжёлой обработки; в фазе 0 замеряем `cpuTime` grammY через `wrangler tail`; если > 5 мс на простой апдейт — тонкий свой клиент на `fetch`.
- **ИИ-ответ только в `ctx.waitUntil`, до 30 с после ответа Telegram** → вебхук сразу отвечает 200, работа в `waitUntil`, `AbortController` на 25 с, при таймауте — «не встиг, надішли ще раз»; показываем `typing`.
- **Откат базы только на 7 дней** → перед любой миграцией прода `npm run backup:prod` (`wrangler d1 export`) в `backups/` (в `.gitignore`); пункт в чек-листе миграции.
- **Cron-слоты общие на аккаунт** (KOXBE тоже использует) → один триггер `*/15 * * * *`, внутри ветвление по локальному времени пользователя.
- **SQLite без RLS** → весь доступ к данным через `src/db/repo.ts`, каждая функция принимает `userId`; тест, что handlers не импортируют `drizzle`/`db` напрямую.

## Модель даних

Время хранится в UTC (`INTEGER` unix ms); «локальная дата» вычисляется по `users.tz`.

**Ядро (фазы 1–2):**
- `users`: `id` (Telegram ID, PK), `first_name`, `tz` (`Europe/Kyiv`), `training_days` (`"1,3,5"`), `remind_time` (`"08:00"`), `weigh_time` (`"07:30"`), `sex`, `birth_year`, `height_cm`, `activity` — последние 4 NULL до фазы 3, `created_at`.
- `exercises`: `id`, `slug` UNIQUE, `name_uk`, `equipment` CHECK in (`barbell`,`dumbbell`,`machine`,`cable`,`bodyweight`), `weight_step_kg` (2.5 / 2 / шаг тренажёра), `min_weight_kg`, `muscle_group`, `cues_uk` (3 строки), `video_url` NULL (зарезервировано).
- `exercise_substitutes`: (`exercise_id`, `substitute_id`) PK.
- `programs`: `id`, `user_id`, `name`, `active` (одна активная на user — частичный UNIQUE).
- `program_days`: `id`, `program_id`, `code` (`A`/`B`), `position`.
- `program_exercises`: `id`, `program_day_id`, `exercise_id`, `position`, `sets`, `rep_min`, `rep_max`.
- `workouts`: `id`, `user_id`, `program_day_id`, `status` CHECK in (`active`,`done`,`abandoned`), `started_at`, `finished_at`, `effort` 1–5 NULL, `note`. Не больше одной `active` на user.
- `workout_sets`: `id`, `workout_id`, `exercise_id`, `set_no`, `weight_kg`, `reps`, `prescribed_weight_kg`, `prescribed_reps`, `skipped`; **UNIQUE(`workout_id`,`exercise_id`,`set_no`)** — повторное нажатие = upsert, не дубль.
- `body_weights`: `user_id`, `local_date`, `weight_kg`; UNIQUE(`user_id`,`local_date`) — последнее за день перезаписывает.
- `processed_updates`: `update_id` PK, `created_at` — дедупликация повторов вебхука; чистится кроном старше 3 дней.
- `reminders_sent`: UNIQUE(`user_id`,`kind`,`local_date`) — крон не шлёт дважды.

**Вычисляется, а не хранится:**
- Назначение на следующую тренировку (вес × повторы) — чистая функция `nextPrescription(history, exercise, rules)` из последних сессий упражнения. Нет таблицы «текущий вес» → нет рассинхрона.
- Следующий день программы (A/B) — из последней `done`-тренировки.
- Рекорды и e1RM (Эпли), среднее веса за 7 дней, недельные итоги.

**Зарезервировано (схема решена сейчас, таблицы создаются в своей фазе):**
- Фаза 3 — еда: `foods` (`id`, `name_uk`, `kcal_100`, `protein_100`, `fat_100`, `carbs_100`, `source` CHECK in (`seed`,`ai_estimate`,`manual`)); `food_aliases` (`alias` lowercase UNIQUE → `food_id`); `meals` (`id`, `user_id`, `eaten_at`, `photo_file_id`, `caption`, `status` CHECK in (`pending`,`confirmed`,`cancelled`), `ai_model`, `ai_raw_json`); `meal_items` (`meal_id`, `food_id`, `grams`, **снимок** `kcal`/`protein`/`fat`/`carbs` на момент подтверждения — правка `foods` не переписывает историю); `nutrition_targets` (`user_id`, `valid_from`, `kcal`, `protein_g`, `fat_g`, `carbs_g`, `reason` CHECK in (`formula`,`trend`,`manual`)).
- Фаза 4 — ИИ: `ai_proposals` (`id`, `user_id`, `kind`, `payload_json`, `status` CHECK in (`pending`,`accepted`,`rejected`,`expired`), `created_at`); `ai_usage` (`model`, `input_tokens`, `output_tokens`, `cost_usd_est`, `purpose`, `created_at`) — для дневного лимита; `chat_turns` (последние ~10 реплик для контекста).

## Архітектура

Публичных страниц нет. Один Worker:

- `POST /tg/<webhook-path>` — вебхук Telegram; проверка заголовка `X-Telegram-Bot-Api-Secret-Token`, дедуп по `update_id`, белый список → иначе тишина и ничего не пишем.
  - Команды: `/start`, `/trening` (начать/продолжить), `/vaga <число>` (или просто число в ответ на напоминание), `/progres`, `/prohrama`, `/nalashtuvannia`; позже `/yizha` (итог дня).
  - `callback_query` — кнопки подходов, замены, оценки, подтверждения еды и предложений ИИ.
  - `photo` → распознавание еды (фаза 3). Прочий текст → ИИ-чат (фаза 4).
- `scheduled()` каждые 15 мин: напоминание о тренировке, о взвешивании, недельный отчёт (вс), `active`-тренировки старше 4 ч → `abandoned`, просроченные `ai_proposals` → `expired`, чистка `processed_updates`.
- Окружения: `preview` (отдельный бот в BotFather + отдельная D1) и `production`. Секреты через `wrangler secret`: `TELEGRAM_BOT_TOKEN`, `TELEGRAM_WEBHOOK_SECRET`, `ANTHROPIC_API_KEY`, `ALLOWED_TELEGRAM_IDS`.
- ИИ: еда — один вызов `claude-sonnet-5-5` со structured output (`output_config.format`, JSON-схема: `items[{name_uk, grams, kcal_100, protein_100, fat_100, carbs_100, confidence}]`, `not_food`). Чат — Tool Runner на `claude-haiku-5-5`, effort `low`, инструменты: `get_recent_workouts`, `get_exercise_history`, `get_weight_trend`, `get_program`, `get_today_food` — только чтение; единственный «пишущий» — `propose_change` → `ai_proposals.pending`. Фото в Anthropic уходит base64 (URL файла Telegram содержит токен бота — не отправлять).

### Фаза 1. Тренировка в зале (ядро, цель — 1–2 недели от старта)
- Сид каталога ~15 упражнений (uk-названия, шаг веса, 3 подсказки техники, пары замен).
- Сид программы full body A/B, 3×/нед (черновик, утверждается в начале фазы под оборудование зала):
  - A: присідання зі штангою 3×6–10, жим лежачи 3×6–10, тяга верхнього блока 3×8–12, жим гантелей сидячи 2×8–12, планка 3×30–45 с.
  - B: румунська тяга 3×6–10, жим ногами 3×8–12, тяга горизонтального блока 3×8–12, віджимання на брусах / жим у тренажері 3×8–12, підйом ніг у висі 3×8–12.
- Поток `/trening`: экран упражнения — «Присідання · 40 кг × 8 · підхід 2/3» + [✅ 8] [−1] [+1] [⚖️ Вага] [🔁 Замінити] [⏭ Пропустити]; одно сообщение редактируется; после последнего упражнения — оценка тяжести 1–5 → итог (объём, рекорды).
- Правила прогрессии (двойная прогрессия, чистая функция):
  1. Нет истории → калибровка: стартовый вес = `min_weight_kg`, человек правит кнопкой [Вага]; вес первой сессии — стартовый.
  2. Все рабочие подходы ≥ `rep_max` → вес + `weight_step_kg`, цель повторов = `rep_min`.
  3. Иначе вес тот же, цель повторов = максимум прошлой сессии + 1 (не выше `rep_max`).
  4. Две сессии подряд хоть один подход < `rep_min` → разгрузка −10%, округление вниз к шагу.
  5. Оценка прошлой тренировки 5/5 → повышение веса откладывается на одну сессию.
  6. Вес всегда кратен шагу упражнения и ≥ `min_weight_kg`.
- Продолжение незаконченной тренировки (кнопки работают после перезапуска клиента), `abandoned` через 4 ч.
- `/progres` (минимум): последние 5 тренировок.
- **Готово, когда** реальная тренировка в зале записана на preview-боте с ≤ 1 нажатием на типичный подход, а назначение следующей совпало с правилами.

### Фаза 3. Питание по фото

### Фаза 4. ИИ-тренер
- Любой текст не-команда → Tool Runner с инструментами только на чтение; ответы опираются на цифры из инструментов.

- Системные правила: боль/травма → не советовать «через боль», рекомендовать врача; никаких назначений веса в обход прогрессии.

## Перевірка

- **Прогрессия (таблица случаев):** все подходы на `rep_max` → +шаг; частично → вес тот же, повторы +1; две неудачи подряд → −10% с округлением к шагу; оценка 5 → удержание; нет истории → калибровка; шаг 2,5 vs 5 кг тренажёра.
  Мутанты: `>=` → `>` в проверке «все на `rep_max`» (тест на ровно `rep_max` краснеет); убрать сброс счётчика неудач; 0.9 → 0.95; убрать округление; не учитывать `skipped`-подходы.
- **Идемпотентность:** один `callback_query` дважды → одна строка `workout_sets`; один `update_id` дважды → обработан один раз; крон дважды за 15 мин → одно напоминание. Мутант: убрать `ON CONFLICT` / UNIQUE → красный.
- **Доступ:** ID не из списка → ни ответа, ни записи в БД; неверный секрет вебхука → 401. Мутант: инвертировать проверку.
- **Слой доступа:** тест-грепом — `src/bot/**` не импортирует `drizzle-orm` и `db` напрямую.
- **Время:** напоминание в 08:00 Europe/Kyiv в дни перехода на зимнее/летнее время (последнее вс октября/марта); локальная дата взвешивания около полуночи.
- **Еда:** `pending`-приём не входит в итог дня (мутант: считать все статусы → красный); `meal_items` хранит снимок — правка `foods` не меняет прошлые дни; второй раз тот же неизвестный продукт берётся из `foods`, без новой оценки; невалидный ответ модели → понятная ошибка, ничего не записано.
- **Норма:** формула Миффлина на известных значениях; < 10 взвешиваний → предложения нет; пороги ±.
- **ИИ-чат:** реестр инструментов не содержит пишущих, кроме `propose_change`; `propose_change` создаёт только `pending`; принятие идёт кодом; лимит расходов блокирует вызов.
- **Платформа:** `cpuTime` на preview для апдейта кнопки и для фото < 10 мс (цифры в `docs/PROGRESS.md`); таймаут ИИ 25 с → сообщение пользователю, без зависшей работы.
- **Ручная:** полная тренировка в зале на preview-боте с телефона перед первым деплоем фазы на prod.
- Браузерных сценариев нет до Mini App.
