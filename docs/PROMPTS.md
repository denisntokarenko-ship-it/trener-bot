# Тренер — промпти покрокової реалізації

Джерело: `docs/PLAN.md`. Одне завдання = одна нова сесія Claude Code = одна гілка = один PR.
Промпти лежать по фазах у `docs/prompts/phase-N.md`: **промпт завдання N.x — у `docs/prompts/phase-N.md`** (так само для «↳ Рев'ю» і «↳ Виправлення» під ним). Цей файл — індекс і правила.

| Фаза | Файл | Завдань | 🔒 | Рев'ю фази |
|---|---|---|---|---|
| 0. Каркас | `docs/prompts/phase-0.md` | 4 (0.1–0.4) | 2 | R-0 |
| 1. Тренування в залі | `docs/prompts/phase-1.md` | 5 (1.1–1.5) | 2 | R-1 |
| 1b. Персоналізація й оформлення | `docs/prompts/phase-1b.md` | 6 (1b.0–1b.5) | 5 | R-1b |
| 2. Метрики й нагадування | `docs/prompts/phase-2.md` | 6 (2.0–2.5) | 4 | R-2 |
| 3. Харчування за фото | `docs/prompts/phase-3.md` | 6 (3.0–3.5) | 4 | R-3 |
| 4. ШІ-тренер | `docs/prompts/phase-4.md` | 5 (4.0–4.4) | 4 | R-4 (фінальне) |

Старт: **0.1 — Sonnet 5.5, effort medium**, у новій сесії в папці проєкту.

## Як користуватись

### Цикл одного завдання
1. **Нова сесія** в папці проєкту. Модель і effort обираєш до першого повідомлення (вказані в заголовку завдання).
2. Вставляєш промпт завдання **цілком**.
3. Агент: ворота → гілка від свіжого `origin/main` → робота → перевірки → блок «Перевірка» → PR.
4. Вердикт `НЕ ГОТОВО` → у тій самій сесії «доробляй обовʼязкові рекомендації».
5. 🔒 → до мержу копіюєш «↳ Рев'ю» під завданням у нову сесію; за потреби — «↳ Виправлення».
6. Мержиш PR сам (Squash and merge), видаляєш гілку. Лише тоді — наступне завдання.
7. Кінець фази → «↳ Рев'ю Фази» під `R-N`. Наступна фаза не стартує, доки воно не закрите.

### Чому так
- Свіжа сесія на завдання: контекст чистий, помилки однієї сесії не перетікають.
- `docs/PROGRESS.md` — єдина памʼять між сесіями: статуси, «Борг», «Рішення», нотатка ≤ 5 рядків.
- Ворота в кожному промпті: попереднє не ✅ на `origin/main` → агент зупиняється.
- Огорожа обсягу: «Робиш» / «НЕ робиш»; поза обсягом — зупинись і спитай.
- Таблиці — у своїй фазі; специфікація — зрізами `docs/spec/phase-N.md`: сесія читає свій зріз + `00-common.md`, а не всю спеку. Зріз фаз 0–1 пише 0.2, далі кожна фаза починається завданням N.0 — коли видно, що вийшло насправді.
- Бюджет: файл, який промпт велить прочитати, ≤ 40 КБ; тримає `npm run check:docs` у CI. Цей індекс і `docs/prompts/*` агент цілком не читає — ти копіюєш блок.
- Деплой у прод — окремим 🔒-завданням наприкінці кожної фази: бот потрібен у залі вже після фази 1, а не після всього MVP.

### Моделі й effort

| Модель | Коли |
|---|---|
| **Opus 5.5** | специфікації, схема, шар даних, безпека вебхука, рушій прогресії, ідемпотентність кнопок і крону, ШІ з інструментами, прод, усі рев'ю |
| **Sonnet 5.5** | каркас і CI, звіти й налаштування поверх готового шару даних, крон за чіткими правилами |
| **Haiku 4.5** | не для коду: ціна помилки вища за економію |

| Effort | Коли |
|---|---|
| **medium** | каркас, CI, текстові звіти, налаштування |
| **high** | специфікація, схема, шар даних, вебхук, прогресія, нагадування, ШІ-чат, більшість рев'ю; Sonnet-завдання з тихою помилкою (корекція норми) |
| **xhigh** | гроші й секрети (розпізнавання фото з лімітом витрат), прод, рев'ю фаз із цим |
| **max** | не за замовчуванням; лише якщо на xhigh рев'ю й автор двічі не зійшлись щодо одного блокера |

Правила: рев'ю не нижче за завдання й не нижче high (скрипт робить сам); виправлення — модель і effort автора; двічі не пройшов «Перевірку» по одному критерію → нова сесія на рівень вище.

### Гілки
- `main` лише через PR (крім першого коміту 0.1). Завдання: `phase-N/NN-коротко`, специфікації: `docs/spec-phase-N`.
- Кожна гілка від свіжого `origin/main` (`git fetch && git switch -c … origin/main`): після squash-мержу локальний main розходиться з віддаленим.
- Рев'ю пише `docs/reviews/<id завдання>.md` у гілку завдання; рев'ю фази — `review/phase-N`, виправлення — `fix/phase-N-review`.

### Субагенти
Лише в рев'ю: один `Explore` для широкого пошуку. У реалізації — ні.

### Позначки
🔒 — рев'ю до мержу. 👤 — робиш ти (BotFather, секрети, ключ Anthropic, створення D1, вибір обладнання й джерела продуктів, тренування в залі); агент готує команду, секрети не вводить.
