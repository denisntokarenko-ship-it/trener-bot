# Фаза 1b — Персоналізація й оформлення

## Стан

**Оновлено:** 2026-11-20 · **Зріз:** специфікація Фази 1b (1b.0) · **Читають:** 1b.1–1b.5 разом із `00-common.md`.
**Рішення замовника:** план будує **код** за таблицями нижче, не ШІ; ті самі відповіді → той самий план. Дані власника не видаляються: нова програма активується, стара архівується (`active = 0`). Припущення — у «Невідоме» (**[П]**); медичних тверджень немає, діапазони перевірити в тренера.

## 1. Опитування

**Питання 7.** Для вправ-якорів за місцем (лише тих, що проходять фільтри §3 для рівня, обмежень і цілі, і без `done`-історії власника): `gym` — присідання зі штангою, жим лежачи, тяга верхнього блока, жим гантелей сидячи; `home` — гоблет-присідання, тяга гантелі в нахилі, жим гантелей стоячи, румунська тяга з гантелями. Кожне: «Знаєш свою вагу у вправі X? [Не знаю] [✍️ Ввести]». Ввід `60x8` / `60×8` / `60 8` / `42,5x10`: вага > 0 і ≤ 400, повтори 1–30; вага округлюється вниз до кроку вправи. «Пропустити» пропускає весь блок. «Не знаю» = калібрування як у Фазі 1. Вага діє лише для тієї вправи; якщо варіант плану її не містить, екран плану каже «Ваги враховано для N із M».

**Потік.**
- Кожна відповідь пишеться в БД одразу; стан у `onboarding_state`, тому перервану анкету продовжують: `/start` при активній анкеті питає [▶️ Продовжити] [🔄 Спочатку].
- Текст приймається лише на кроці, що чекає текст; інакше — звичайне «Не зрозумів».
- Кнопка несе крок: `o:<крок>:<значення>`; не збігся з поточним — застаріла: `answerCallbackQuery` «Це вже неактуально» + екран поточного кроку. Повторна відповідь — upsert, без дубля.
- Власник з активною програмою: `/start` — звичайне привітання + [📝 Налаштувати персональний план], не примус. `/profil` — перегляд (перший рядок «🎯 Ціль: …», уточнення під ним, «📋 Активний план: <програма>») і [🔄 Пройти знову]: Q1 знову обовʼязкове, поточні відповіді позначені ✅. Відповіді пишуться одразу, тож кинуте повторне проходження лишає нові відповіді, а активний план — старий (це видно в «Активний план»).
- Текст: якщо активне тренування чекає вагу (`await_input`), текст іде їй, не анкеті; команда скидає `await_input`, анкета лишається на кроці.

## 2. Модель даних

Міграція `0002` (1b.1), час — UTC мс, доступ лише через `src/db/repo.ts` з `userId`.

**`user_profiles`** (`user_id` PK → `users.id`): `goal` IN (`lose_fat`,`muscle`,`recomp`,`strength`,`health`,`other`); `goal_note` ≤ 300; `level` IN (`novice`,`mid`,`adv`); `days_per_week` 2–5; `session_min` IN (30,45,60,90); `place` IN (`gym`,`home`); `limits` — прапорці через кому з {`knee`,`back`,`shoulder`,`wrist`}, `''` = немає; `limits_note` ≤ 300; `sex` IN (`m`,`f`); `birth_year` 1930–2020; `height_cm` 120–230; `weight_kg` 30–300; `meals_per_day` 1–5; `diet_note` ≤ 300; `sleep_band` IN (`lt6`,`6_7`,`7_8`,`8p`); `activity` IN (`low`,`mid`,`high`); `created_at`, `updated_at`. Усе, крім ключа й часу, nullable; `goal NULL` = анкета не пройдена. Вага — знімок анкети, не журнал Ф2.

**`onboarding_state`** (`user_id` PK): `status` IN (`active`,`done`); `step` IN (`welcome`,`goal`,`goal_note`,`level`,`days`,`minutes`,`place`,`limits`,`limits_note`,`lifts`,`sex`,`birth`,`height`,`weight`,`meals`,`diet`,`sleep`,`activity`,`plan`); `sub` 0–3 (підпитання ваг); `msg_id`; `plan_variant` 0–2; `started_at`, `updated_at`. Стан — лише крок; відповіді лежать у профілі й `start_weights`.

**`start_weights`**: `user_id`, `exercise_id` → `exercises.id`, `weight_kg` ≥ 0, `reps` 1–30, `created_at`; PK (`user_id`,`exercise_id`).

**Стартові ваги → прогресія.** Єдина зміна в `progression.ts`: `nextPrescription(history, exercise, slot, start?)`, `start: { weightKg, reps } | null`. Правило 1 без історії: є `start` → вага = `start.weightKg`, якщо `start.reps ≥ slot.repMin`, інакше `× 0,9`; далі звичайна нормалізація до кроку й `min_weight_kg`; повтори `repMin`; причина `calibration`, [⚖️ Вага] лишається. Є історія — `start` ігнорується; без `start` — як у Фазі 1 (тести без змін). Вага з повторами < `repMin` → × 0,9. `start_weights` читає repo, не домен.

**`activatePlan(userId, plan)`** — один батч D1: стара програма `active = 0` → нова `active = 1` + дні + слоти; `programs_one_active` лишається гарантією. `workouts`/`workout_sets` не чіпаються. Є `active`-тренування → відмова `ACTIVE_WORKOUT` без запису: «Заверши тренування (/trening) і повтори». Нові id — `INSERT … SELECT` (як сид), програму знаходять за `id`, не за назвою (вона не унікальна). Стартові ваги в слоти не пишуться: живуть у `start_weights` (діють лише без історії вправи, стару програму не чіпають).

**Каталог** — нові nullable-стовпці `exercises` (заповнює сид; `pattern NULL` для `buildPlan` не існує): `pattern` IN (`squat`,`hinge`,`hpush`,`vpush`,`hpull`,`vpull`,`core`,`delt`,`legacc`); `kind` IN (`compound`,`accessory`); `place` IN (`gym`,`both`); `min_level` 1–3; `stress` — прапорці як у `limits`. Рук окремо немає (`muscle_group` без перебудови таблиці не розширити).

## 3. Генератор плану

`buildPlan(profile, catalog, variant) → Result<Plan, NO_GOAL | EMPTY_DAY>` — чиста функція `src/domain/plan.ts`: без I/O, `Date.now` і випадковості. `Plan = { name, days: [{ code, title, slots: [{ exerciseId, sets, repMin, repMax }] }] }`. `EMPTY_DAY` — день вийшов із < 2 слотів: екран «Не вдалося скласти план із такими обмеженнями» + [🦵 Змінити обмеження] [⏱ Змінити тривалість] [🔄 Спочатку], у `programs` нічого.

**Спліт.** Дні програми крутяться по колу (як `nextDayCode`); «днів на тиждень» впливає лише на текст.

| Днів | `novice`, `mid` | `adv` |
|---|---|---|
| 2 | Все тіло A, B | Все тіло A, B |
| 3 | Все тіло A, B | Штовх, Тяга, Ноги |
| 4 | Верх, Низ | Верх, Низ |
| 5 | Штовх, Тяга, Ноги, Верх, Низ | те саме |

Коди (≤ 8): `FA FB UP LO PU PL LG`. Назва програми: «План: <ціль>».

**Патерни дня** (порядок = пріоритет, день обрізається до N слотів):

| День | Патерни |
|---|---|
| Все тіло A | squat, hpush, vpull, vpush, core, hinge, delt |
| Все тіло B | hinge, squat, hpull, hpush, core, vpull, delt |
| Верх | hpush, hpull, vpush, vpull, delt, core, hpull |
| Низ | squat, hinge, legacc, squat, core, legacc, hinge |
| Штовх | hpush, vpush, hpush, delt, core |
| Тяга | vpull, hpull, hpull, delt, core |
| Ноги | squat, hinge, squat, legacc, core |

N за `session_min`: 30 → 4, 45 → 5, 60 → 6, 90 → 7 (день коротший — скільки є). Обрізання N — до модифікаторів цілі.

**Добір вправи.** Кандидати патерну: `place` сумісне (`home` — лише `both`); `min_level` ≤ рівня; `stress` не перетинається з `limits`; для `health` не штанга. Порядок — `id` зростаючи. n-те входження патерну в дні бере кандидата `(n + variant + d) mod len`, де `d` — позиція дня в програмі з 0; якщо вже вжитий у цьому дні — наступний за колом. Порожній патерн: `vpull→hpull`, `legacc→hinge`, `vpush→hpush`, інакше слот пропускається.

## 4. Назви тренувань

`program_days.title TEXT` (nullable, ≤ 40). `code` лишається ключем у `callback_data`, назва туди не потрапляє. Показ: `title ?? "День " + code`.

| Код | Назва |
|---|---|
| A, FA · B, FB | Все тіло A · Все тіло B |
| UP · LO | Верх · Низ |
| PU · PL · LG | Штовх · Тяга · Ноги |

**Де:** вибір дня й екран `/trening`, підсумок, `/prohrama`, `/progres`, показ плану, нагадування Фази 2. Літералів «День A/B» у `src/bot/**` немає (тест-греп).

**Міграція.** `0002`: `UPDATE program_days SET title = 'Все тіло A' WHERE code = 'A' AND title IS NULL` (і `B`) — ідемпотентно; `code` не міняється, `workouts.program_day_id` цілі. Старі дні після `activatePlan` лишаються, `/progres` показує їхні назви.

## 5. Підтвердження плану

Після питання 15 бот будує план за `plan_variant` і показує: «План: <ціль>», «N днів · ~X хв», по дню — назва й `вправа · підходи × повтори`; обмеження — «⚠️ Враховано: коліна». Кнопки (`o:pl:ok|alt|days`):
- [✅ Прийняти] — `activatePlan` + стартові ваги; `status = done`; «Готово, наступне: <день>».
- [🔁 Інший варіант] — `plan_variant = (v + 1) mod 3`, перебудова.
- [✏️ Змінити дні] — крок `days` → `minutes` → новий план; `plan_variant = 0`.
До [✅ Прийняти] у `programs`/`program_days` нічого не пишеться: стару програму не зачеплено, анкету можна кинути. Повторне [✅] після `done` — застаріла кнопка. Показ ≤ 4096 символів (тест на межі: 5 днів × 7 слотів).

## 6. Гайд оформлення

Тексти — лише в `src/bot/texts.ts`; `parse_mode: HTML`; користувацькі рядки (імʼя, нотатки, назви) — через `esc()` (`& < >`).
- **Тон:** на «ти», коротко, тепло без награності; без канцеляриту, суржику й русизмів («наступний», не «слідуючий»). Помилка = що сталося + що робити.
- **Формат:** жирним — заголовок, назва вправи, ключові числа; курсивом — підказки; `<code>` — приклади вводу. Один емодзі на початку заголовка й по одному на кнопці.
- **Емодзі:** 🏋️ тренування · 🎯 ціль · 📋 програма · 📈 прогрес · ✅ записано · ⚠️ увага · ❌ помилка · 💡 техніка · 🎥 відео · ⚖️ вага · 🔁 заміна · ⏭ пропуск · 🏆 рекорд · 🍽 їжа · 😴 сон. 
- **Довжини:** екран ≈ 12 рядків / 1200 символів (жорстко ≤ 4096); кнопка ≤ 24 символи, ≤ 3 в рядку; `callback_data` ≤ 64 байти.
- **Шаблони:** *вправа* — `<b>Назва</b>`, «Підхід 2/3 · ціль 60 кг × 8», історія, кнопки підходу, [🎥 Відео] окремим рядком; *підсумок* — «🏋️ <день> · N хв», рекорди 🏆, оцінка; *програма* — «📋 <назва>», дні, «Наступне: <день>»; *порожній стан* — що буде + команда; *помилка* — «❌ <що>. <що робити>», загальна — `SOMETHING_WRONG`.
- **Меню (`setMyCommands`):** start Почати · trening Тренування · prohrama Програма й наступне заняття · progres Останні тренування · profil Профіль і план.
- **Опис бота:** `setMyDescription` ≤ 512, `setMyShortDescription` ≤ 120 символів; `scripts/set-bot-profile.ts` (тексти з `texts.ts`), ідемпотентно.

## 7. Звʼязок з Фазою 3

Анкета збирає для норми: `sex`, `birth_year`, `height_cm`, `weight_kg`, `activity`, `goal` (колонка «напрям»), `meals_per_day`, `diet_note`, `sleep_band`. Завдання 3.2 лише рахує норму (Міффлін — Сан Жеор, активність, дельта від цілі) і пише `nutrition_targets`; `NULL`-поле запитує в людини.

## 8. Історії

**P1 — Опитування**

## 9. Відео техніки

`exercises.video_url` (поле є, `NULL`) заповнює сид 1b.1 для **всіх 30** вправ. Лише `https://www.youtube.com/watch?v=<11 символів [A-Za-z0-9_-]>` або `https://youtu.be/<11 символів>`, ≤ 200 символів; формат перевіряє `isVideoUrl` (сид відмовляє, екран не показує кнопки).

**Підбір (агент сид-завдання перевіряє сторінку, а не довіряє пошуку):** відео існує; показує саме цю вправу; ≤ 8 хв; не Shorts. Мова: українська → російська → англійська. Надійного немає — `NULL` і рядок у «Борг» `PROGRESS.md`, вигаданих посилань не пише. Список «вправа → посилання» — у PR.

**Якщо відео зникне:** у рантаймі не перевіряється (N1); людина бачить помилку YouTube, бот цілий. Правка — оновити сид. Автоперевірка поза межами.
