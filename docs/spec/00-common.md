## Терміни

- **Власник** — єдина людина, якій бот відповідає; її Telegram ID — у білому списку.
- **Апдейт** — один об'єкт `Update` від Telegram з унікальним `update_id`.
- **Програма** — набір днів (`A`, `B`), активна одна на користувача.
- **Слот** — рядок `program_exercises`: вправа на позиції дня + `sets` × `rep_min`–`rep_max`.
- **Тренування** — один візит у зал за одним днем програми; рядок `workouts` у стані `active` → `done` або `abandoned`.
- **Підхід** — один рядок `workout_sets`: вага × повтори або позначка «пропущено».
- **Сесія вправи** — усі підходи однієї вправи в одному тренуванні.
- **Робоча вага сесії (W)** — вага останнього (за `set_no`) непропущеного підходу сесії. **Робочі підходи** — непропущені підходи сесії з вагою W.
- **Призначення** — вага × цільові повтори на наступну сесію вправи. Обчислюється чистою функцією з історії й не зберігається окремо; знімок лягає в `workout_sets.prescribed_*`.
- **Калібрування** — сесія вправи без зарахованої історії: стартова вага = `min_weight_kg`, людина править її кнопкою [⚖️ Вага]; вага цієї сесії стає стартовою.
- **Розвантаження** — зниження ваги на 10 % з округленням вниз до кроку після двох невдач поспіль.
- **Крок ваги** — `weight_step_kg`: найменша зміна ваги для вправи (0 — вага тіла).
- **Оцінка тяжкості** — 1–5 після тренування (1 — легко, 5 — на межі); `workouts.effort`.
- **Локальна дата** — календарна дата моменту UTC у часовому поясі `users.tz`.
- **Застаріла кнопка** — `callback_query`, чиї дані не відповідають поточному стану тренування.

## Ролі

- **Власник** — Telegram ID з секрету `ALLOWED_TELEGRAM_IDS` (через кому). Може все, що вміє бот. Роль одна.
- **Будь-хто інший** — для бота не існує: відповідь Telegram 200, жодного повідомлення, жодного запису в БД. Порожній чи відсутній список — доступу немає нікому (fail closed).
- ШІ у фазах 0–1 відсутній. З фази 3 він лише класифікує або пропонує; записи робить код після кнопки людини.

## Нефункціональні вимоги

- **N1. CPU ≤ 10 мс на виклик Worker** (ліміт Free; з 2026-11-20 хостинг на платному акаунті — ліміт вищий, N1 лишається ціллю продуктивності; очікування I/O не рахується). Ціль — медіана ≤ 5 мс на простий апдейт; міряється `cpuTime` з `wrangler tail`, цифри — у `docs/PROGRESS.md`. Медіана > 5 мс — тонкий клієнт на `fetch` замість grammY.
- **N2. Вебхук відповідає 200 до роботи ШІ.** Усе довше за звичайний запит до D1 і Telegram — у `ctx.waitUntil`, `AbortController` на 25 с; таймаут → «Не встиг, надішли ще раз». Фази 0–1 ШІ не мають.
- **N3. Ідемпотентність.** Апдейт з тим самим `update_id` обробляється не більше одного разу. Повторне натискання тієї самої кнопки не створює другого запису (`UNIQUE` + upsert). Повторний запуск крону не змінює результату.
- **N4. Час.** У БД — UTC мс (`INTEGER`). Часовий пояс за замовчуванням — `Europe/Kyiv`; локальна дата й день тижня — з `users.tz`, з урахуванням переходу на літній/зимовий час.
- **N5. Мова інтерфейсу — українська:** усі тексти, кнопки, назви вправ. Команди — латиницею транслітом (`/trening`).
- **N6. Ліміти Telegram.** Текст повідомлення ≤ 4096 символів (формувач гарантує це сам, тест на межі); `callback_data` ≤ 64 байти; текст `answerCallbackQuery` ≤ 200 символів.
- **N7. Секрети** (`TELEGRAM_BOT_TOKEN`, `TELEGRAM_WEBHOOK_SECRET`, `ANTHROPIC_API_KEY`, `ALLOWED_TELEGRAM_IDS`) — лише `wrangler secret` / `.dev.vars`; не в репозиторії, не в логах, не в повідомленнях. URL файлу Telegram (містить токен) нікуди не передається.
- **N8. Доступ до даних** — лише через `src/db/repo.ts`, кожна функція приймає `userId`; чужий рядок для неї не існує.
- **N9. Помилка обробника** — лог без секретів і без тексту повідомлень, Telegram отримує 200 (без шторму повторів), власнику — «Щось пішло не так, спробуй ще раз», якщо відправка можлива.
- **N10. Бюджет:** хостинг: платний акаунт Cloudflare (з 2026-11-20; раніше $0 на Free), ШІ ~$1–2/міс.
